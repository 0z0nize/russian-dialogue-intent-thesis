# Черновик инструкций по разметке интентов диалогов

Документ описывает черновую версию инструкций для ручной разметки интентов в диалогах из датасета `d0rj/dialogsum-ru`. Используется совместно с CSV-файлом `data/annotation/dialogue_intent_annotation_v1.csv`, который создаётся ноутбуком `notebooks/02_annotation_prep.ipynb`.

## Колонки CSV-файла

- **dialog_id** — уникальный идентификатор диалога. Берётся из поля `id` датасета `dialogsum-ru`, если оно есть, иначе формируется из индекса строки в train-сплите. Используется как первичный ключ при объединении с другими таблицами.
- **split** — название сплита датасета, из которого взят диалог. На данный момент всегда `train`.
- **dialogue** — полный текст диалога одной строкой (с переносами строк между репликами). Это основной объект разметки.
- **summary** — краткое резюме диалога из исходного датасета. Может быть полезно как подсказка для аннотатора, но не должно заменять прочтение самого диалога.
- **n_utterances** — приблизительное число реплик в диалоге, рассчитанное автоматически (по переносам строк или маркерам говорящих). Используется как метаданное, не подлежит ручному изменению.
- **dialogue_words** — приблизительное число слов в `dialogue`. Метаданное.
- **summary_words** — приблизительное число слов в `summary`. Метаданное.
- **primary_intent** — основной (доминирующий) интент диалога. Заполняется аннотатором вручную. На этапе v1 — свободная строка из черновой типологии (см. ниже).
- **secondary_intent** — дополнительный интент, если в диалоге явно прослеживается второй смысловой пласт. Допустимо оставлять пустым.
- **is_ambiguous** — флаг неоднозначности диалога (0 / 1). Значение `1` ставится, если аннотатор не уверен в выборе `primary_intent` или диалог одинаково хорошо подходит под несколько категорий.
- **annotation_notes** — свободные комментарии аннотатора: пояснения к выбору метки, выявленные особенности, идеи для уточнения схемы.
- **annotator** — идентификатор аннотатора (инициалы / ник). Нужно для отслеживания согласованности разметки между аннотаторами.
- **label_version** — версия схемы разметки. На данный момент `v1`. При изменении набора интентов или правил версия инкрементируется.

## Открытые вопросы и плейсхолдеры для будущих правил

### Что считается «основным» интентом

- Как формально определить «основной» интент, если в диалоге несколько коммуникативных целей?
- Использовать ли критерий по числу реплик, посвящённых теме, или по итоговому результату диалога?
- Как поступать с приветствиями / прощаниями / small talk: считать их отдельным интентом или игнорировать?

### Диалоги с несколькими темами

- Когда уместно использовать `secondary_intent`, а когда лучше выставить `is_ambiguous = 1`?
- Допустимо ли более двух интентов? (Текущая v1 — нет; фиксируется только primary + secondary.)
- Как описывать переходы между темами в `annotation_notes`?

### Неоднозначные случаи

- Что делать, если диалог обрывается и интент не успевает «раскрыться»?
- Как поступать, если интент одного говорящего отличается от интента другого?
- Критерии установки `is_ambiguous = 1` — нужно зафиксировать чек-лист.

### Использование `secondary_intent`

- Заполнять только при явном втором смысловом пласте или всегда при наличии нескольких тем?
- Должен ли `secondary_intent` принадлежать той же типологии, что и `primary_intent`?

### Версионирование меток

- Изменения в наборе допустимых меток → инкремент `label_version` (`v1` → `v2`).
- Малые уточнения формулировок при неизменном наборе меток — фиксировать в этом документе без смены версии.
- Старые разметки сохраняются как отдельные CSV с суффиксом версии.

### Технические договорённости

- Кодировка CSV — UTF-8, разделитель — запятая.
- Пустые значения в `primary_intent` / `secondary_intent` означают «ещё не размечено».
- `is_ambiguous` имеет тип int, допустимые значения — 0 и 1.
- Изменения схемы интентов фиксируются в этом документе и отражаются в `label_version`.
